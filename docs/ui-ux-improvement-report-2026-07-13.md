# UI/UX 改善レポート

実施日: 2026-07-13 / ブランチ: `feat/ui-ux-improvements`（起点: `feat/extension-token-lifecycle`）

監査方法: 開発サーバー（`next dev`）に対して headless Chrome（Playwright）で実際に操作。
未ログイン・ログイン済（セッション Cookie を生成して注入）の両方で、デスクトップ 1280px / タブレット 768px / モバイル 390px の 3 画面幅を巡回し、クリック・検索・モーダル開閉・ページ送りなどの操作を実行して確認した。

## 3. 改善した内容と理由

方針: **既存の情報構造・データ取得ロジックは変えず、プレーン CSS（globals.css）でデザインルールを整備して壊れた UI を修復**。Tailwind 導入（ADR-0001 で決定済み）はビルド基盤に触る大きな変更のため今回は見送り、導入後も流用できるトークン設計にした。

### 全画面共通

- **globals.css を全面整理**: CSS 変数によるデザイントークン（配色・余白 4px 刻み・角丸 6/10px・影 2 段階・フォントサイズ 4 段階）と、共通クラス `.btn`（primary/secondary/danger/sm）、`.status-box`（ローディング/空/エラー）、`.modal-*`、`.page-title`/`.section-title` を定義（問題 6, 7, 14, 22 対応）
- **レスポンシブ対応**: 800px 以下でサイドバーを上部の横並びナビへ切り替え。ヘッダーは検索優先でタイトルを隠し、カードグリッドは `auto-fill` で可変（問題 2）
- **二重入れ子の解消**: `layout.tsx` の `<header>` ラッパー削除、`sidebar.js`/各ページの `.sidebar`・`.main-content` 重複を除去（問題 19）
- **フォーカス可視化**: `:focus-visible` の共通アウトラインを追加（キーボード操作対応）

### 個別画面

| 対象 | 改善 | 理由 |
|---|---|---|
| モーダル | オーバーレイ+パネルとして修復。`role="dialog"`、Escape/背景クリックで閉じる、失敗時のエラーメッセージ、作成中 disabled、未ログイン時はログイン案内、一覧のローディング表示 | 問題 1, 8 |
| ヘッダー | アバターの即ログアウトを廃止し、クリックでメニュー（名前表示・アカウント・ダッシュボード・ログアウト）を開くドロップダウンに変更。未ログイン時は「ログイン」ボタンを明示。placeholder 日本語化、/search の q を検索欄へ反映 | 問題 4, 12。ダッシュボードはサイドバーから到達不能だったため導線も確保 |
| サイドバー | `usePathname` + `aria-current="page"` で現在位置をハイライト。ラベルを「ホーム/アカウント/マイビデオ/マイリスト」に統一。ブランド名をサイドバー上部に配置 | 問題 10 |
| 一覧（クリップ/プレイリスト） | ページャをボタン化し「n ページ目」を表示。スピナー付きローディング、案内文付き空状態、再試行ボタン付きエラー、**401 時は「ログインが必要です」+ ログインボタン** | 問題 5, 7, 14 |
| クリップ行 | タイトル+補足情報の 2 行構成に整理し、アクションを「▶ Netflix」（tooltip: この場面を再生）と「＋」（tooltip: プレイリストに追加）のボタンに統一 | 問題 16 |
| プレイリストカード | カード全体をクリック可能に（「go」ボタン廃止）。ホバーで枠線+影 | 問題 13 |
| プレイリスト詳細 | 見出し・再生ボタンをスタイル化、クリップ件数表示、行をカード化、ドラッグハンドルに tooltip、**削除前に confirm**、空状態メッセージ追加 | 問題 9 |
| ログイン | ダミーフォームを撤去し、説明文＋「Google でログイン」1 ボタンのカードに。/registration は /login へリダイレクト | 問題 3。ADR-0002（Google 一本化・ダミー削除）に準拠 |
| アカウント | プレースホルダーの「設定」セクションを削除。ページタイトル追加。連携/解除ボタンを共通スタイル化、解除に confirm | 問題 15, 17 |
| ダッシュボード | 未ログイン表示を status-box 化、ログアウトを danger ボタンに | — |
| 404 / done | カスタム 404（ホームへ戻る導線付き）を新設、/done を日本語化 | 問題 18 |
| メタデータ | `<title>` を「サブスク切り抜き」に（旧: My App） | — |

付随修正: root `page.js` の誤った `"use server"` を削除（設計監査 Phase 1 の横展開漏れ。my_video では修正済みだった同一問題）。

## 4. 整理したデザインルール

`src/app/globals.css` 冒頭の `:root` にトークンとして定義。今後の UI はこのトークンと共通クラスに乗せる。

- **配色**: ブランド = ネイビー `#2d445d`（既存サイドバー色を昇格）。hover `#3d627a` / active `#24374b`。背景 `#f5f5f5`、面 `#fff`、罫線 `#e2e5e9`、本文 `#1f2937`、補足 `#6b7280`、危険 `#dc2626`、フォーカス `#2563eb`
- **余白**: 4/8/12/16/24/32px の 6 段階（`--space-1`〜`--space-6`）
- **角丸**: ボタン・入力欄 6px、カード・モーダル 10px、円形 9999px
- **影**: カード hover 用 `--shadow-sm`、モーダル/メニュー用 `--shadow-md`
- **文字**: 13/15/18/22px の 4 段階。ページ見出し `.page-title`、セクション見出し `.section-title`
- **ボタン**: `.btn` + `.btn-primary`（主要操作・画面に原則 1 つ）/ `.btn-secondary`（通常操作）/ `.btn-danger`(破壊的) / `.btn-sm`。disabled は透明度 50%
- **状態表示**: 非同期 UI は必ず「ローディング（`.spinner`）・空・エラー・（必要なら）401」の 4 状態を `.status-box` で表現し、空/エラーには次のアクション（案内文・再試行・ログイン）を添える
- **破壊的操作**: 実行前に `confirm` で確認する
- **現在位置**: ナビゲーションは `aria-current="page"` を付け、CSS はそれをフックにハイライトする

## 6. 動作確認内容

- **主要操作**: ＋ボタン→モーダルが中央にオーバーレイ表示 ✔ / Escape・背景クリックで閉じる ✔ / 作成ボタンが入力空で disabled ✔ / ヘッダー検索→ /search 遷移、検索欄に q が残る ✔ / ページャで 2 ページ目へ ✔ / プレイリストカードクリックで詳細へ遷移 ✔ / ユーザーメニュー開閉（Escape・外側クリック）✔
- **画面幅**: 390px でサイドバーが上部ナビ化し本文が全幅 ✔ / 768px ✔ / 1280px ✔
- **ローディング**: 一覧初期表示でスピナー+説明文 ✔
- **空状態**: 検索ヒットなしで「「q」に一致するクリップは見つかりませんでした。」✔ / プレイリストなしで作成方法の案内 ✔
- **エラー状態**: /playlists 未ログインで「ログインが必要です」+ ログインボタン ✔ / モーダル内 401 でログイン案内 ✔ / 404 でカスタムページ+ホーム導線 ✔
- **コンソール**: 改善後の巡回で新規の JS エラーなし（401/404 のリソースログのみ。401 は未ログイン時の想定挙動）
- **リグレッション**: `npx biome check .`（エラー/警告 0）、`npm run typecheck`、`npm test`（account 8 + search 8 全パス）、`npm run build` 成功

## 7. 今回は実装しなかった追加改善案

1. **Tailwind v4 の正式導入**（ADR-0001 / 設計監査 Phase 2）: 依存追加とビルド設定変更を伴うため見送り。導入時は今回の CSS トークンを `@theme` へ移植すれば共通クラスは段階的に置換できる
2. **`(protected)/layout.tsx` による認証ガード一元化**（設計監査 Phase 1-2）: 今回はクライアント側の 401 表示改善で対処。layout 化する場合は `/done`（拡張機能のログイン完了画面）を `(protected)` の外へ出す判断が必要
3. **データ取得の Server Component 一本化**（ADR-0003 / Phase 3）: `clipCluster`/`playlist` の建て替えは既存挙動を壊すリスクが大きく、UI 改善と分離すべき
4. **削除操作の `location.reload()` 廃止**: `router.refresh()` + 楽観的更新に置き換えるとちらつきが消えるが、並べ替え状態との整合を要検討
5. **プレイリスト並べ替えの永続化**: 現在ドラッグ&ドロップはローカル state のみで、リロードすると元に戻る（API 呼び出しが未実装）。UI ではなく機能の欠落のため今回は据え置き
6. **モーダルのフォーカストラップ**: Escape/背景クリックは実装済みだが、Tab 移動がモーダル外に抜ける。`<dialog>` 要素への移行が本筋
7. **クリップ行の情報設計**: 開始/終了時刻の表示、サービスアイコン画像化など
8. **`/clipAppRouter/[id]` の Not Found 表示**: 生の `<h1>Not Found</h1>` のまま（利用経路が拡張機能のみのため低優先）
9. **トースト通知**: プレイリスト追加成功時に画面遷移せず「追加しました」を出す UX も検討余地あり（現在は該当プレイリストへ遷移することでフィードバックしている）
